Open https://colab.research.google.com/ and choose File > Upload notebook.
No paid Colab plan, Earth Engine account, API key or guaranteed GPU is needed.
Run cells in order. Cells marked "Supplied" contain code you can run as given;

PURPOSE

Imagine helping archaeologists plan a survey: image review identifies locations
worth checking against records, inspecting in better imagery or visiting in the field.
The exercise assumes a first pass of 50 image reviews so we can compare rankings
at the same effort. This is a teaching budget; a real team can review more as time permits.
Enki supplies labelled tell/negative image examples for training and evaluation.
We also use Cyprus data, but its settlement catalogue records locations and occupation
periods, not whether archaeology is visible in each image or absent elsewhere.
The Cyprus images therefore support inspecting transfer and identifying missing
evidence. A project intended for Cyprus would need appropriate local image labels.

DEFAULT WORKFLOW

The notebooks contain frozen DINOv2-small embeddings, a pinned Cyprus catalogue,
and twelve real Sentinel-2 image chips with provenance. At first run they retrieve
a balanced 600-image Enki sample using about 73 MB of HTTP byte-range downloads.
The download uses original ZIP-directory offsets and verifies every member's CRC.
Decoded pixel hashes are then checked against the feature cache. No full 1.7 GB
training archive or 12 GB test archive is needed.

Both notebooks use the cached features on CPU. Model extraction and live imagery
acquisition are preparation utilities, outside the notebooks' main path.

Both representations start from the same 64 x 64 RGB input, including Cyprus.
DINO then enlarges this input to 224 x 224; both frozen caches were regenerated.
Old caches and changed image pixels are rejected. Restart the kernel and rerun
setup after updating a notebook; personal *-Copy notebooks remain snapshots.

CORE PATH AND TIME

Allow about 3¼ hours for the core path, including discussion, a short
break and routine setup support. The four-hour schedule adds one optional lab and
room for further discussion or catch-up. This is an estimate for basic Python/pandas users;
slow downloads or unfamiliar software can add time. The calculation and checkpoints
are in FACILITATOR_GUIDE.md.

Run sections 1–5 in order. Section 2 works through an invented label list, section
3.4 prints the three counts needed for precision and recall, asks for two divisions
and checks the answers before comparing both models. Section 4
changes the review budget, and section 5 compares two pairs of Cyprus images then
asks for three calculations: paired agreement, shortlist catalogue fraction and
catalogue recovery. Section 5.3 supplies counts, three blanks, a check and random
references. The instructor copy supplies worked answers. Keep one Cyprus calculation
for the final recommendation.
Keep brief notes for one five-sentence recommendation in section 6.

The optional block is BEFORE section 6. Choose ONE lab, or skip it:
  A. Complete three PCA expressions and compare 2D/3D feature projections (25–35 min).
  B. Complete a training function; compare 20/50 training images and two seeds with
     the full model, then inspect tells entering or leaving the shortlist (25–35 min).
  C. Implement image similarity search; retrieve Enki neighbours of two real Cyprus
     pairs and compare their appearance, labels and classifier scores (25–30 min).

For A, complete and run the function before enabling RUN_PROJECTION.
For B, complete the three feature/label selections, then enable RUN_LABEL_EXPERIMENT.
Run 20 images/seed 0, 50 images/seed 0, and 20 images/seed 1. Keep brief comparison notes.
For C, complete the two similarity/ranking expressions, then enable RUN_CYPRUS_NEIGHBOURS.
Start with C_PAIR_IDS = ["CY754"], then try ["CY479"]. Record an image match and its limits.
The default participant copy skips all optional code. The instructor copy includes
the image galleries and worked B/C results; participants are not
expected to finish all labs. No new model weights or imagery downloads are needed.
Lab C's neighbour labels belong to Enki images, not the Cyprus queries. Section 5.3
supplies the actual catalogue-agreement measurement for the final recommendation.

The main comparison uses fixed C=1, chooses using validation recall at 50 reviews
(AP breaks a tie), and reuses that model for the mistake and Cyprus reviews.
Section 6 has three steps: use the evidence summary to write five sentences; export
and share team_submission.zip AND your saved notebook; then enable REVEAL_TEST.
The final table compares validation and test at the saved review budget. Add one
debrief sentence and save the notebook again, keeping your original recommendation.
Do not use test performance to select another model. A blank recommendation produces
a draft; finish it and rerun export before sharing.

The instructor notebook contains worked results from the real sample. They describe
this curated split, not promised performance on other archaeological landscapes.

SCIENTIFIC SCOPE

This is a new teaching split drawn from the Enki training archive. The six hundred
images contain 300 source-negative images and 300 source-positive images from
five RGB landscape categories. Explicitly masked and black-and-white positive
folders are excluded. Similar-image filtering removes some duplicates, but the
archive does not provide verified site identities or geographic grouping. The
holdout is therefore not a geographic-generalisation benchmark or a secure blind
competition. Source labels remain recoverable from the public archive.

The retained sample has 300 tell images at 350 x 350; negatives include 249 at
64 x 64 and 44 at 350 x 350. The original dimensions alone predict validation
labels well. Common 64-pixel preprocessing reduces this detail shortcut; it does
not match metres per pixel or eliminate all source/acquisition differences.
Section 3 reports a training-derived size-only baseline and validation AP within
each original size, alongside the positive fraction. Single-class strata have
undefined AP. The evidence ZIP now also includes data_audit.json,
validation_diagnostics.csv and transfer_diagnostics.csv.

Cyprus chips are 1 km windows at 10 m/pixel from 5 August 2024. They support an
interpretation and domain-shift exercise, not archaeological visibility ground
truth. Nearby background locations are unlabelled, not confirmed absences. The
notebooks explicitly avoid reporting detection accuracy for this sample.
Section 5 compares both models' score ranges with Enki validation. A whole-sample
shift to low or high scores cannot establish local archaeological absence or
presence. The necessary next step is representative local imagery, expert labels
for visible target features, and separate geographic assessment locations.
The Cyprus calculations measure catalogue agreement, not detection accuracy.
Exact pair ties receive half credit, and ties at the shortlist cutoff are flagged.
cyprus_catalogue_metrics.csv and cyprus_pairs.csv preserve the numerical evidence.

EDITING AND VALIDATION

src/archaeology_challenge/runtime.py contains the shared helpers bundled in both notebooks.
One folded setup cell extracts them as archaeology_workshop/assets/workshop_helpers.py.
build_notebooks.py generates the notebooks, reusing their bundled data. A fresh
checkout can rebuild without the original .work/ preparation cache.
prepare_workshop.py and select_enki_sample.py record the data-preparation recipe.
check_notebooks.py checks metrics, submission ID alignment, duplicate handling,
catalogue conflicts, both model paths in Cyprus, exports and notebook/source agreement.
It can execute the instructor plus a participant copy on the real sample.

The .work/ directory contains preparation caches and validation artifacts. The
notebooks do not import these local scripts or depend on .work/ when shared.

For package installation and optional dependencies, see README.md.

Rebuild after editing:
  uv run --locked --extra dev python build_notebooks.py
  uv run --locked --extra dev python check_notebooks.py --execute

Regeneration clears saved outputs; the execution step restores instructor outputs.
The participant validation copy is written only under .work/.
